# Experiment Tracking for Machine Learning

Experiment tracking helps you record what you tried, which data and code you used, how a model performed, and where its artifacts were saved. It makes ML work easier to compare, reproduce, debug, and share.

## Learning objectives

By the end of this module, you should be able to:

- Explain runs, parameters, metrics, tags, and artifacts.
- Log model hyperparameters and evaluation metrics.
- Compare model experiments using a consistent table.
- Save experiment metadata and results.
- Understand how MLflow supports local and team-based experiment tracking.
- Apply reproducibility, data privacy, and artifact management practices.

## Core concepts

| Concept | Meaning | Example |
|---|---|---|
| Experiment | A collection of related runs | `customer-churn-baseline` |
| Run | One execution of training/evaluation | Logistic regression with `C=1.0` |
| Parameter | A setting chosen before or during training | `max_iter=1000` |
| Metric | A numeric result | `accuracy=0.91` |
| Tag | Searchable descriptive label | `stage=baseline` |
| Artifact | A file produced by a run | model, chart, report, feature list |
| Run ID | Unique identifier for a run | Generated by the tracking system |

## Why track experiments?

Without tracking, results can be lost in notebook outputs, terminal history, or manually edited spreadsheets. A tracking system makes it easier to answer:

- Which configuration produced the best validation score?
- Was the model trained with the same features and data version?
- Can we reproduce the run?
- Where are the model and evaluation artifacts?
- Did a change improve the metric we actually care about?

## Setup

This module uses a lightweight local JSON/CSV workflow first, then introduces MLflow as an optional tracking backend.

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux:
source .venv/bin/activate

python -m pip install --upgrade pip
python -m pip install numpy pandas scikit-learn matplotlib mlflow jupyter
jupyter notebook
```

Open `examples.ipynb` and run the cells from top to bottom. The notebook generates a synthetic classification dataset, so no dataset download is required.

## MLflow quick start (optional)

The notebook includes a small MLflow example. In a terminal, you can view local runs with:

```bash
mlflow ui --backend-store-uri ./mlruns
```

Then open the local address printed by MLflow in your browser. Local tracking data is stored in the `mlruns/` directory by default when using a local file-based tracking setup. MLflow configuration can vary by version; consult the official documentation for the current recommended setup.

## Good experiment-tracking practices

- Choose metrics before running experiments; use validation data for model selection and reserve test data for final evaluation.
- Log parameters, data identifiers, code revision, library versions, and evaluation metrics.
- Keep run names and tags consistent.
- Record random seeds, but remember that seeds alone do not guarantee identical results across every platform and library.
- Never log passwords, access tokens, personally identifiable information, or raw sensitive records.
- Keep artifacts in access-controlled storage and apply retention policies.
- Track the preprocessing pipeline and feature schema, not only the estimator.
- Avoid selecting a model using the final test set repeatedly.
- Document failed or incomplete runs when they provide useful diagnostic information.
